# Оркестратор / Ресурсы

Элементы для работы с общими ресурсами (Assets) и учётными данными, хранящимися в Оркестраторе.

> ⚠️ Требуется **Primo RPA Studio Enterprise** с подключённым Оркестратором.

## Что такое ресурс

Ресурс (Asset) — это именованное значение, хранящееся в Оркестраторе централизованно. Все роботы могут читать его по имени. Это удобно для параметров, которые меняются: URL сервиса, порог суммы, адрес получателя — достаточно изменить значение в Оркестраторе один раз, и все роботы сразу получат новое значение без переразработки.

Отдельный тип ресурса — **Credential** (учётные данные): логин + пароль в зашифрованном виде. Пароль не хранится в коде процесса и не виден разработчику.

## 📋 Элементы

| Элемент | Что делает и когда нужен |
| :--- | :--- |
| **Получить ресурс** | Считывает значение ресурса из Оркестратора по его имени. Поддерживает типы String, Integer, Boolean, DateTime и другие. Нужен, когда параметр процесса должен управляться централизованно — без изменения кода робота. |
| **Установить ресурс** | Изменяет значение ресурса в Оркестраторе. Нужен, когда робот должен сам обновить общий параметр — например, записать дату последнего успешного запуска или обновить счётчик. |
| **Получить учетные данные** | Считывает логин и пароль из ресурса типа Credential. Основной безопасный способ получить учётные данные в процессе — пароль не виден в коде и не хранится в переменных в открытом виде. |
| **Установить учетные данные** | Обновляет логин и пароль в ресурсе типа Credential. Нужен при ротации паролей — чтобы обновить их в Оркестраторе без ручного вмешательства. |
| **Заблокировать ресурс** | Устанавливает или снимает блокировку ресурса для других роботов. Нужен, когда несколько роботов работают с одним ресурсом одновременно — блокировка не даёт им конфликтовать: пока один робот использует ресурс, другой ждёт. |
