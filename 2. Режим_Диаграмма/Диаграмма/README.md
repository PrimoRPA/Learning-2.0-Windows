# Диаграмма

Элементы для построения логики процесса в виде блок-схемы (Flowchart). В отличие от режима «Последовательность», где шаги идут строго сверху вниз, в режиме «Диаграмма» каждый элемент соединяется со следующим стрелками — это делает ветвления и переходы наглядными даже при сложной логике.

> Эти четыре элемента — базовые строительные блоки любой диаграммы. Остальные элементы (Excel, Браузер, Почта и т.д.) точно такие же, как в режиме «Последовательность» — просто размещаются внутри диаграммы.

## 📋 Элементы

| Элемент | Что делает и когда нужен |
| :--- | :--- |
| **Диаграмма** | Контейнер, внутри которого строится весь граф процесса. Это «холст», на котором размещаются все остальные блоки и соединяются стрелками. Может быть вложена в другую диаграмму или в последовательность — например, когда один сложный участок процесса удобнее показать как блок-схему, а всё остальное оставить линейным. |
| **Последовательность** | Блок внутри диаграммы, который объединяет несколько шагов в единый узел. На схеме выглядит как один прямоугольник, но внутри содержит полноценную последовательность действий. Нужен, чтобы не превращать диаграмму в хаос из десятков связанных элементов — логически связанные шаги собираются в один блок, и схема остаётся читаемой. |
| **Принятие решения** | Узел ветвления: проверяет условие и направляет поток по одной из двух стрелок — «Да» или «Нет». Визуальный аналог If-Else. Нужен, когда процесс должен идти по-разному в зависимости от данных — например, «если документ согласован → отправить», «если нет → вернуть на доработку». На схеме сразу видно, куда ведёт каждый исход. |
| **Состояние** | Узел, представляющий отдельное состояние процесса. Содержит три секции: вход (Entry — действия при входе в состояние), основное (что делать в этом состоянии) и выход (Exit — действия при выходе). Стрелки между состояниями задают переходы. Нужен для процессов с конечным автоматом — например, статусная модель документа: «Черновик → На согласовании → Утверждён → Отклонён». |
